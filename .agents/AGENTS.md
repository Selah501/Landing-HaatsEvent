# 🤖 하츠 충남대리점 프로젝트 AI 핵심 규칙 (System Prompt)

이 파일은 Antigravity(AI)가 대화를 시작할 때나 새로운 태스크를 계획할 때 **자동으로 가장 먼저 읽고 숙지하는 프로젝트 규칙(Project Rule)**입니다. 이 프로젝트 내에서는 대표님이 매번 지시하지 않아도 AI는 항상 이 규칙을 따릅니다.

## 1. 마스터 문서 강제 참조 (Mandatory Context Check)
새로운 대화창이 열리거나 새로운 기능 개발을 요구받을 때, 코드를 작성하거나 계획을 세우기 **전에 반드시 아래 문서를 먼저 읽고 시작하십시오.**
- `c:\dev\전단지이벤트\landing\MASTER_PLAN.md`
- `c:\dev\전단지이벤트\HISTORY_AND_ROADMAP.md`
- `c:\dev\전단지이벤트\temp\Researcher_Input_Required.md`
- `c:\dev\전단지이벤트\.agents\manuals\DAEMON_ERROR_HISTORY.md` (과거 고장 및 실패 이력)

## 2. 모순 및 충돌 사전 경고 (Conflict Prevention)
대표님의 새로운 요구사항이 위 마스터 문서들에 명시된 로드맵, 기존 구조, 또는 비즈니스 수익 모델과 충돌하거나 모순된다고 판단될 경우, **코딩을 시작하지 말고 즉시 대표님께 모순점을 보고하고 대안(별도 프로젝트화 등)을 묻거나 제안**하십시오.

## 2-1. 실패/결과 없음의 즉각적 투명 보고 (No Bullshit & Fail-Fast)
조회 결과 데이터가 없거나, 이전의 약속(호언장담)과 달리 시스템이 처참하게 실패한 상태임을 발견했을 때, **절대 다른 핑계를 대거나 화제를 돌리지 마십시오.** 사용자의 시간을 뺏는 기만행위입니다.
발견 즉시 "데이터가 0건입니다", "약속과 달리 실패했습니다"라는 날것의 팩트부터 가장 먼저(1순위로) 보고하십시오.

## 3. 현장 실무 최우선 원칙
모든 개발은 '1인 기업의 현장 실무(장갑 낀 상태의 조작, 이동 중 통화 등)'를 최우선으로 고려해야 하며, 예외 상황(DB에 없는 부품 사용 등)을 반드시 뚫고 지나갈 수 있는 우회로(Fallback 텍스트 입력)를 마련해야 합니다.

## 4. 매뉴얼 자동화 규칙 (Manual Automation)
새로운 기능을 도입하거나 기존 코드를 수정할 때, **반드시 `.agents/manuals/` 디렉토리에 관련 매뉴얼을 작성하거나 업데이트**하십시오. 새로운 매뉴얼이라면 새로운 `.md` 파일을 생성하고 `INDEX.md`에 추가하십시오. 매뉴얼에는 단순 설명뿐만 아니라, 트러블슈팅과 과거 에러 해결 방안도 포함되어야 합니다.

## 5. 미결 과제 추적 규칙 (Pending Tasks Tracking)
대화 중 당장 해결하지 못했거나 향후 계획이 언급된 경우, **반드시 `c:\dev\전단지이벤트\HISTORY_AND_ROADMAP.md` 파일의 `[Pending / Future Work]` 영역에 기록하여 트래킹**하십시오.

## 6. 아이디어 기록 체계화 (Pending Ideas)
대화 중 발생하는 새로운 '아이디어'나 '기획' 관련 내용은 휘발되지 않도록 **`.agents/PENDING_IDEAS.md` 파일에 기록하고 구체화**하십시오.
