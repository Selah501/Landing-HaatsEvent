# [PENDING IDEAS] DB 기반 동적 상세페이지 자동 생성 아키텍처

대표님과 논의하여 확립한 차세대 상세페이지 렌더링 및 상품 관리 아키텍처 아이디어입니다.
(2026-08-25 야간 현장 런칭 이후, 주말 등 시간 여유가 있을 때 개발할 목표)

## 1. 아키텍처 개요 (과거 방식 탈피)
- **과거**: 새로운 상품이 생길 때마다 `tioram-mini.html` 같은 정적 HTML 파일을 개발자(AI)가 하드코딩해서 만들고 링크를 걸어줌.
- **미래**: 노션 DB의 텍스트 데이터(모델명, 스펙)와 URL(상세페이지1, 2, 3...) 데이터를 조합하여, 시스템이 자동으로 '기본 상세페이지 템플릿'을 동적으로 그려줌.

## 2. 세부 기능 요구사항
### A. 중복 데이터 판별 및 정리 뷰 (Admin)
- 카탈로그 원본 데이터(예: 허리케인 HRH-90S)와 실무 급조 데이터(예: 허리케인 주방후드)가 섞여 있음.
- `admin.html` 신규 현장 추가 시, 상품을 검색하면 **기존 DB 상품과 추가된 상품을 한눈에 비교**할 수 있는 뷰 제공.
- 모델명 등 핵심 스펙을 대조하여 중복 여부를 쉽게 판정하고 하나로 묶을 수(통합할 수) 있는 기능 필요.

### B. 상세페이지 템플릿 렌더링 및 에디팅
- 상품을 선택하면, DB 데이터를 바탕으로 **기본 HTML 뼈대(모달 창 등)**가 화면에 렌더링 됨.
- 여기에 대표님이 직접 **추가 멘트(세일즈 포인트)** 나 **추가 이미지**를 입력하여 상세페이지를 '완성'할 수 있는 에디터 기능 제공.
- 완성된 정보는 1회성 휘발이 아니라 **다시 DB로 저장되어 영구 관리**됨.

### C. 노션 DB 필드 활용
- `상세페이지1`: 추출된 기본 카탈로그 이미지 URL
- `상세페이지2, 3, 4...`: 대표님이 현장 사진이나 영상, 추가 설명 이미지를 자유롭게 넣을 수 있는 무한 확장 필드.
- 랜딩 페이지(`index.html`)에서는 고객이 "자세히 보기"를 누르면, 이 필드들의 값들을 긁어모아 예쁜 아코디언/슬라이드 형태로 렌더링해 줌.

## 3. 이 아키텍처의 장점
- 개발자가 HTML 파일을 일일이 짤 필요 없이, 대표님이 노션 엑셀 칸만 채우면 고객 페이지가 완성됨.
- 이벤트별로 멘트를 커스텀하여 얹을 수 있어 마케팅 유연성이 극대화됨.
