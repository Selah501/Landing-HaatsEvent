# 🎨 하츠 충남대리점 전용 "상세페이지 메이커" (AI 가이드라인)

이 문서는 AI가 상세페이지를 제작할 때 **무조건 지켜야 하는 작업 지침(가이드라인)**입니다.
대표님께서는 언제든 이 파일을 열어 템플릿 내용이나 규칙을 자유롭게 수정하실 수 있습니다.

## 🤖 1. 에이전트 행동 수칙 (절대 규칙)
1. **환각(새로운 이미지 창조) 절대 금지**: 제공된 원본 이미지에서 픽셀 단위로 자르기(Crop)만 수행하며, 없는 이미지를 지어내지 않습니다.
2. **가격 정보 배제**: 상세페이지 내부에는 가격과 관련된 어떠한 텍스트도 들어가지 않습니다. (단, 이벤트 특가 등 대표님 명시적 지시가 있는 경우는 제외)
3. **톤앤매너**: "하츠 충남대리점의 전문 기사가 직접 시공한다"는 신뢰감을 주는 문구를 적극 활용합니다.
4. **[중요] 히어로 이미지 (첫 이미지) 룰**: 각 상세페이지의 가장 첫 번째 이미지(ex: 10년이 넘으셨나요?)는 **반드시 해당 현장에 부착된 전단지 상단 캡쳐 이미지**를 동일하게 배치하여 이질감을 없애야 합니다.
5. **[중요] DB 마스터 이미지 룰**: 옵션이나 본문에 들어가는 예쁜 시공 이미지(예: snow_install.png)는 단순 HTML 내 경로 변경에 그치지 말고, **Supabase `products` 테이블의 해당 상품 `detail_urls` 필드에 영구 저장(Update)한 뒤 연동**해야 합니다. 임의로 카탈로그 URL로 대체하지 마십시오.

## 📐 2. 상세페이지 4단계 템플릿 (기본 레이아웃)
AI는 아래 4단계 구조에 맞춰 HTML을 조립해야 합니다. (모바일 최적화 필수)

- **[1단계] 도입부 (Hook)**: 고객의 불편함 공감 및 제품 핵심 매력 어필 (쿠팡/카탈로그 이미지 활용)
- **[2단계] 시각적 신뢰 (시공 사례)**: 제공된 현장 비포/애프터 사진을 배치하고 전문성을 강조.
- **[3단계] 핵심 스펙 (표 형태)**: 도면 이미지를 넣고, 주요 소재/크기/풍량 등의 데이터를 깔끔한 `<table`>로 정리.
- **[4단계] 필수 안내사항 (CS 방어)**: 기존 자바라 사용 안내 등 특이사항 고지.

## 🔄 3. 작업 파이프라인 (AI가 수행할 순서)
1. **분석 및 크롭**: 사용자가 채팅창에 올린 이미지를 파이썬 `Pillow` 라이브러리로 분석 및 필요한 영역만 크롭.
2. **HTML 생성**: 위 4단계 템플릿에 맞춘 단일 `html` 코드 생성 (CSS는 기존 스타일 가이드 준수).
   - 이때 `products` 테이블의 `detail_pages` 항목에 들어갈 제목(`title`)은 항상 `"AI 생성 버전 (YY.M.D)"` 형식으로 통일합니다 (예: `"AI 생성 버전 (26.9.8)"`).
3. **저장 및 확인**: 작업한 HTML 코드를 **Supabase의 `products` 테이블 내 `detail_pages` 필드(JSONB 배열)**에 최신 버전으로 INSERT (또는 업데이트) 합니다. 더 이상 로컬 디렉토리(`landing/public/products/`)에 물리적인 `.html` 파일로 생성하여 저장하지 마세요. 반드시 상품마스터 DB에 연동하여 저장한 뒤, 사용자에게 검토 요청을 합니다.
4. **수정 및 배포**: 사용자의 피드백에 따라 코드를 수정하고, DB 버전을 갱신합니다. 최종 승인 시 상품마스터 모달에서 확인 가능하도록 안내합니다.

## 🚀 4. 현장 이벤트 셋업 워크플로우 (이벤트(전단지) 등록)
대표님께서 "전단지 현장 등록해줘" 또는 "이벤트 세팅해줘"라고 하실 때, 아래 **(a) ~ (d) 구조**를 기반으로 작업합니다.

*   **(a) 랜딩 화면 (전단지 인입)**: 고객이 QR 코드를 찍고 들어오면 보이는 `index.html`. 진행 중인 아파트 현장 리스트가 노출됨.
*   **(b) 현장별 도입 문구 (Hero Title)**: 특정 현장을 클릭 시 펼쳐지는 영역 최상단에 노출되는 후킹 멘트. 관리자 페이지(`admin.html`)의 이벤트 등록 모달창에서 **'현장별 도입 문구'** 필드에 작성. (예: "여름철 눅눅한 욕실...")
*   **(c) 메인 상품**: 해당 현장의 핵심 시공 상품 1개. (클릭 시 (a)에서 만든 상세페이지 URL 연동)
*   **(d) 같이 바꾸면 좋은 상품 (옵션)**: 메인 상품 하단에 나열되는 연계 상품 리스트.

**작업 순서:**
1. 필요한 상세페이지(c, d)가 모두 제작되었는지 확인 (없으면 먼저 상세페이지 제작 진행).
2. 관리자 페이지(`admin.html`)에 등록할 이벤트 정보(현장명, 가격, **도입 문구(b)** 등)를 취합.
3. **옵션 구성 룰**: 해당 아파트 현장에 설치된 기존 후드를 기준으로 **상위 호환(업그레이드)** 제품만 옵션으로 노출합니다. (예: 테라 현장 ➔ 허리케인, 스노우 옵션 제공 / 허리케인 현장 ➔ 테라 제외, 스노우 옵션 제공 / 허리케인도어 현장 ➔ 무도어, 허리케인, 스노우 제공)
4. 데이터 세팅을 수동으로 할지, AI가 스크립트를 통해 Firebase DB에 찔러넣을지 대표님과 조율하여 진행.
