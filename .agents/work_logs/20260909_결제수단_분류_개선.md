# 🛠 결제수단 분류 기준 개편 및 데이터 호환성 보장 작업 요약 (2026-09-09)

## 1. 개요
*   **작업 목적**: 과도하게 파편화되어 있던 결제수단 선택지를 5가지 항목으로 간소화하고, 과거에 저장된 구형 데이터들이 새로운 선택지에 맞춰 화면에서 호환되도록 처리함. 추후 재무장부 합계 로직 연동을 위한 기초 작업.
*   **매핑 기준 (5종)**
    *   `이체(우리 개인)` (기존 계좌이체 등 통합)
    *   `이체(우리 기업)` (기존 우리은행사업자)
    *   `카드(우리기업)` (신규 추가 및 기존 법인카드 대체)
    *   `현금` (유지)
    *   `기타` (기존 현장 카드결제, 카카오뱅크, 케이뱅크 통합)

## 2. 주요 변경 사항
*   **`admin_v2.html` (작업지시서)**
    *   결제수단 콤보박스 선택지를 상기 5가지로 변경.
    *   `mapPaymentMethod()` 공용 함수를 도입하여, DB에서 옛날 텍스트(예: "카카오뱅크")를 불러올 경우 화면에는 "기타"로 자동 치환하여 출력하도록 함 (과거 데이터가 화면에 보이지 않거나 깨지는 현상 방지).
*   **`erp.html` (재무장부)**
    *   거래처 및 일일 지출 내역 등록 시 동일하게 5가지(외상매입금 포함 6종) 콤보박스로 변경.
    *   장부 목록 렌더링 시 `mapPaymentMethod()` 함수를 태워서 과거 내역들도 5가지 기준으로 통일감 있게 출력되도록 UI 조정.

## 3. 핵심 기술 의사결정
*   **DB 무수정(비파괴) 렌더링 방식 채택**: DB 테이블 내부의 과거 텍스트 원본을 스크립트로 일괄 수정하는 마이그레이션 방식은 위험도가 높다고 판단하여 기각. DB 데이터는 100% 보존한 상태에서, 프론트엔드 단에서 화면 렌더링 시점에만 값을 가로채어 치환하는 방식을 사용하여 완벽한 안정성 확보.
