# 판매가계산기 및 상품마스터 역할 분리 및 연동 버그 수정 (2026-09-17)

## 🎯 작업 목표
- 기존 상품마스터에 혼재되어 있던 "원가"와 "마진율/판매가" 개념을 명확히 분리.
- 상품마스터: 매입가(원가) 관리 및 검색 전용 페이지로 전환.
- 판매가계산기: 설치비, 추가옵션을 고려한 '최종 판매가 설계' 전용 툴로 개편.

## 🛠️ 주요 작업 내역
1. **상품마스터 UI 개편 (product_master.html)**
   - 가격 편집 영역을 "읽기 전용(Read-only)" 뷰어로 변경.
   - 단, 유일하게 '제품 원가(매입가)' 항목만 직접 수정할 수 있도록 개방.
   - 복잡한 `div` 박스들을 하나로 모아 공간 효율성을 극대화하고 직관적으로 렌더링.
   - "판매가 계산기로 가기" 다이렉트 링크 버튼 추가.

2. **판매가계산기 이력 연동 로직 (price_calculator.html)**
   - 계산된 금액을 Firebase/Supabase의 `product.details.price_histories`에 배열(최대 4개)로 누적 저장하는 기능 신설.
   - 계산기 목록에서 제품 클릭 시 즉각적으로 이력(최근 저장 내역)을 렌더링하도록 훅(Hook) 연결.
   - 저장된 견적 내역의 [삭제] 버튼 추가로 관리 편의성 증대.

3. **상품마스터 - 판매가계산기 데이터 파이프라인 (URL Param)**
   - 계산기에서 `🚀 상품마스터에 적용` 버튼 클릭 시, 계산된 항목들(기본설치비, 옵션비용, 최종합계 등)을 URL 파라미터(`?apply_product_id=...&install=...`)로 실어서 상품마스터로 보냄.
   - 상품마스터가 파라미터를 읽어 즉시 모달을 띄우고 숨겨진 Input 및 가시적 텍스트를 업데이트하도록 구현.

4. **치명적 버그 수정 (Troubleshooting)**
   - 증상: 상품마스터 모달에서 '저장' 버튼을 누르면 모달이 무한 반복해서 다시 열림.
   - 원인: 저장 후 테이블 목록을 리로드(loadProducts)할 때 URL 파라미터에 여전히 `apply_product_id`가 남아 있어 트리거가 무한 루프를 돌림.
   - 해결: 모달이 처음 띄워질 때 `window.history.replaceState`를 사용해 즉시 URL에서 파라미터 꼬리를 잘라버리도록 수정.
